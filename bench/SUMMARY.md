## Observations

1. ExoPlayer's default buffer added 41 ms to the median (502 vs 461 ms), and the two ranges overlap almost completely (417–553 vs 331–550), so 5 runs don't show a clear difference. Media3 1.11.1's default `bufferForPlaybackMs` is 1000 ms, and the gap from first byte to first audio was 90–363 ms across all 10 valid HTTP runs.
2. Sending text at 40 ms per word instead of all at once raised the WebSocket median from 552 to 1103 ms (+551 ms). With `chunk_length_schedule: [50]` and the same 40 ms per word, it dropped to 542 ms. This suggests the extra delay comes from the server holding text until a character threshold before generating, not from the word rate itself.
3. WebSocket runs varied less from run to run: the 0 ms/word spread was 56 ms (533–589), against 219 ms for HTTP with the 250 ms buffer.

## How each number is measured

The timer start and stop points are unchanged from the original code.

- **HTTP firstByteMs:** from `speak()` to the first `onBytesTransferred` of the response.
- **HTTP firstAudioMs:** from `speak()` to ExoPlayer's `onIsPlayingChanged(true)`. That is when the player starts, slightly before sound leaves the speaker.
- **WebSocket firstAudioMs:** from just before the socket opens to the first PCM chunk received; the chunk is then queued to the `AudioTrack`. `firstByteMs` is set to the same value, so it's omitted above.

The two modes stop the clock at different points, so the HTTP vs WebSocket comparison is approximate. Observation 1 compares HTTP to HTTP, and observation 2 compares WebSocket to WebSocket. Observation 3 compares across modes, but only how much each one varies, not which one is faster.

## Changes made for the benchmark

- One `TTFA_BENCH` CSV logcat line per run from `finishRun`, plus a `success` flag (finished normally and produced audio).
- A debug-only batch started by adb intent extras (`bench/run_matrix.sh` runs the five setups).
- A fixed 141-character benchmark text.
- An optional `generation_config.chunk_length_schedule` in the WebSocket's first message (`--eia chunkSchedule 50`), used only by `ws-40-chunk50`. Without it, the first message is unchanged and the server default applies.
- The previous WebSocket run's `AudioTrack` is now released before the next run starts. Before, each run left one open. This does not touch the timers.

## Notes

- The warm-up runs were 1739 ms (http-default), 612 ms (http-lowlatency), 533 ms (ws-0), 1420 ms (ws-40) and 872 ms (ws-40-chunk50) to first audio. They are in `results.csv` and excluded above.
- Context for observation 2, worked out from the text rather than measured: `BENCH_TEXT` is 26 words, and the sender waits 40 ms after each one. The text reaches 50 characters at word 9 (320 ms of send delay) and 120 characters at word 21 (800 ms). ElevenLabs documents 120 as the first default threshold. The measured difference (561 ms) is in the same range as that 480 ms, but it isn't a 1:1 match, so the data supports this explanation rather than proving it.
- `ws-40` was not re-run alongside `ws-40-chunk50`, so part of the difference could come from network conditions changing between the two sessions. Both sets were tight (1099–1126 and 519–585 ms).

## Reproduce

Needs `adb`, a device with USB debugging, `ELEVENLABS_API_KEY` in `local.properties`, and bash 4 or newer (the script uses associative arrays; macOS ships bash 3.2, so install a newer bash there). The full matrix uses 4,230 characters of ElevenLabs quota (30 runs × 141).

```bash
./gradlew installDebug
ADB=/path/to/adb bench/run_matrix.sh                 # all five setups, appends to bench/results.csv
ADB=/path/to/adb bench/run_matrix.sh ws-40-chunk50   # or only the named setups
./gradlew :app:testDebugUnitTest --tests '*BenchReportTest*'
```

The script appends to `bench/results.csv`, and the report groups rows by setup name, so move the existing file aside before a fresh run, or a re-run setup gets mixed with the old one. The last command writes the results table to `app/build/bench/summary-table.md`. A single batch can also be started by hand:

```bash
adb shell am start -S -n com.gbegovic.voicedemo/.MainActivity --es mode ws --ei tokenDelayMs 40 --eia chunkSchedule 50 --ei runs 6
adb logcat -s TTFA_BENCH TTFA_BATCH
```
