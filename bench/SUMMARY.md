## Observations

1. ExoPlayer's default buffer added 41 ms to the median (502 vs 461 ms), and the two ranges overlap almost completely (417–553 vs 331–550), so 5 runs don't show a clear difference. Media3 1.11.1's default `bufferForPlaybackMs` is 1000 ms, not ~2.5 s, and the gap from first byte to first audio was 90–363 ms across all 10 valid HTTP runs.
2. Sending text at 40 ms per word instead of all at once raised the WebSocket median from 552 to 1103 ms (+551 ms).
3. WebSocket runs were more consistent: the 0 ms/word spread was 56 ms (533–589), against 219 ms for HTTP with the 250 ms buffer.

## How each number is measured

The timer start and stop points are unchanged from the original code.

- **HTTP firstByteMs:** from `speak()` to the first `onBytesTransferred` of the response.
- **HTTP firstAudioMs:** from `speak()` to ExoPlayer's `onIsPlayingChanged(true)`. That is when the player starts, slightly before sound leaves the speaker.
- **WebSocket firstAudioMs:** from just before the socket opens to the first PCM chunk received; the chunk is then queued to the `AudioTrack`. `firstByteMs` is set to the same value, so it's omitted above.

The two modes stop the clock at different points, so the HTTP vs WebSocket comparison is approximate. Observation 1 compares HTTP to HTTP, and observation 2 compares WebSocket to WebSocket.

## Changes made for the benchmark

- One `TTFA_BENCH` CSV logcat line per run from `finishRun`, plus a `success` flag (finished normally and produced audio).
- A debug-only batch started by adb intent extras (`bench/run_matrix.sh` runs the four setups).
- A fixed 141-character benchmark text.
- The previous WebSocket run's `AudioTrack` is now released before the next run starts. Before, each run left one open. This does not touch the timers.

## Notes

- The warm-up runs were 1739 ms (http-default), 612 ms (http-lowlatency), 533 ms (ws-0) and 1420 ms (ws-40) to first audio. They are in `results.csv` and excluded above.
- The comment in `HttpStreamingPlayer.kt` that says ExoPlayer's defaults wait for ~2.5 s is out of date for Media3 1.11.1 (1000 ms), and has been left unchanged.
